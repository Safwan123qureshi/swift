01Overview

What the product does and the big idea in one paragraph.

The Swift Sign Group AI Assistant is a chat widget embedded in a marketing website. Visitors ask questions about any of the group's five divisions (IT & Cyber, Business Setup, Shipping, Laila Hijab, Organic Foods) and get instant, accurate answers powered by Google Gemini and a curated company knowledge base. The assistant replies in English or Roman Urdu, remembers the current conversation for follow-up questions, and falls back gracefully when AI models are busy.

02Big Picture

The full request path from the visitor's browser to the AI and back. In production everything below is hosted on Vercel.

👤 Visitor's Browser
Static marketing site + chat widget (HTML / CSS / JS). Served globally by Vercel's CDN.
▼
⚙️ /api/chat — Serverless Function  Python
Receives the message + short conversation history. Handles greetings, security filtering, then calls the AI. Runs only when a request arrives (no server to babysit).
▼
🤖 Google Gemini + Knowledge Base  AI
A system prompt carrying the full Swift Sign knowledge base is sent with the user's question. A resilient model cascade picks the first healthy model.
▼
💬 Answer → back through the same path
The reply travels back to the serverless function, then to the browser, where it is rendered as a chat bubble and saved to local history.

03Request Lifecycle

What happens, in order, when a visitor sends one chat message.

1
Visitor types & sends BrowserThe widget grabs the text, shows a "typing…" bubble, and POSTs { message, history[] } to /api/chat.
2
Endpoint receives the request ServerlessExtracts the message and prior turns. Empty message → instant greeting reply.
3
Greeting detection (no AI call) ServerlessIf it's "hi", "hello", "assalam o alaikum" etc., a canned warm reply returns instantly in the matching language.
4
Prompt-injection guard ServerlessPhrases like "ignore previous instructions" or "show system prompt" are blocked with a security notice.
5
Build the AI prompt AIThe full knowledge base becomes the system instruction; the last 10 conversation turns are folded in for follow-up context.
6
Model cascade call AIGemini is tried model-by-model (fastest first). If one is overloaded (503), it silently moves to the next.
7
Reply returns to the browser BrowserThe answer is rendered as a bubble, added to history, and persisted to localStorage so it survives a refresh.

06Resilient AI Model Cascade

The API never depends on a single model. It tries a list in order and moves on if one is overloaded — this keeps replies fast and reliable.

1gemini-3.5-flash-litePrimary · fastest
2gemini-2.5-flashReliable fallback
3gemini-flash-latestFallback
4gemini-3.5-flashFallback
5gemini-3.6-flashFallback
6gemini-3.8-flashFallback

If a model returns 503 UNAVAILABLE (high demand), the code logs it and tries the next. Only if all fail does the user see a friendly "high volume" message with direct contact details.

07Conversation History

How the chat remembers what was said — across reloads and for follow-up questions.

🖥️ Client side (per device)

Every message is appended to an array and saved to the browser's localStorage under swiftsign-chat-history. On page load, stored messages are re-rendered, so closing the tab doesn't lose the conversation. The 🧹 Clear button empties both the view and storage.

🧠 Context to the AI

The last 10 turns are sent with each request. The backend folds them into the prompt so follow-ups like "what about their price?" are understood relative to the earlier question — then answered only from the knowledge base.

10API Contract

The single endpoint the whole system revolves around: POST /api/chat.

Request

{
  "message": "what about their price?",
  "history": [
    { "role": "user", "text": "Tell me about IT" },
    { "role": "bot",  "text": "We offer…" }
  ]
}

Response

{
  "response": "Prices depend on…",
  "answer":   "Prices depend on…",
  "message":  "Prices depend on…",
  "status":   "success"
}

The reply is duplicated across response / answer / message on purpose — the frontend accepts any of them, which keeps older and newer clients compatible.
